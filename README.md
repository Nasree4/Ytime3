# YTime2 Web

## การแก้ไขล่าสุด (26 ตุลาคม 2026)

- เริ่มต้นด้วยรายชื่อว่าง ผู้ใช้เพิ่มชื่อและ UDID ผ่านแบบฟอร์มเอง ไม่มีข้อมูลส่วนบุคคลตั้งต้นในโค้ดหรือ placeholder; ข้อมูล localStorage ของผู้ใช้เดิมยังคงอยู่

- การส่งลงเวลาแสดงสำเร็จเฉพาะรหัสยืนยัน `[001-IN]` / `[001-OUT]` จาก API; ข้อผิดพลาดหรือคำตอบที่ไม่ยืนยันจะแจ้งให้ตรวจประวัติก่อนส่งซ้ำ และไม่สร้างเวลาปรับแก้อัตโนมัติ
- วันที่/เวลาในฟอร์มใช้กับปุ่มปรับรายงานเฉพาะเบราว์เซอร์ ส่วนปุ่มส่งลงเวลาใช้เวลาของเซิร์ฟเวอร์และประเภทเข้า/ออกตามคำตอบ API
- CRUD และการแก้เวลาในตารางเก็บเฉพาะเบราว์เซอร์ แยกตามเจ้าหน้าที่และแถว รองรับแก้วันที่/เวร/ล้างเวลา รวมถึงคืนค่าแถวที่ซ่อนทั้งข้อมูล API และแถวสร้างเอง
- คีย์เก่าที่ระบุเจ้าหน้าที่ยังอ่านได้ ส่วนคีย์ที่ไม่มีเจ้าของและแถวสร้างเองที่ไม่มี `profileId` ยังคงเก็บไว้ แต่ไม่แสดงข้ามเจ้าหน้าที่ รายงานที่พิมพ์แสดงหมายเหตุว่าอาจมีข้อมูลปรับแก้
- ยกเลิกประวัติบุคลากรที่ฝังในโค้ด ใช้ API สำหรับทุกราย; ต้องระบุ UDID จริง จึงจะดึงประวัติได้
- นำปุ่มสคริปต์แก้หน้าจอเว็บโรงพยาบาลออก เพราะไม่ได้เปลี่ยนฐานข้อมูลจริง

ตรวจตรรกะด้วย `node --experimental-strip-types --test scripts/attendance.test.mjs`.
ทดสอบเบราว์เซอร์ด้วย `node scripts/attendance-browser-test.mjs` หลังเปิด dev server ที่ `http://127.0.0.1:5193` (หรือกำหนด `TEST_BASE_URL` เป็น localhost อื่น) และมี Playwright พร้อม browser ในเครื่อง สามารถกำหนด `PLAYWRIGHT_MODULE` และ `TEST_BROWSER_CHANNEL` เช่น `msedge` ได้ การทดสอบใช้ browser context แยกและจำลอง API ทั้งหมด ไม่ส่งข้อมูลลงเวลาจริง

เว็บแอปสำหรับบุคลากรที่ใช้งาน YTime2 1.0.0 เดิม สร้างจากหน้าจอและปลายทาง API ที่ตรวจพบใน APK โดยใช้ฐาน API ที่ผู้ใช้ให้มา: `https://choaironghospital.org`.

## การทำงาน

- ดึงข่าวสารและรายการหน้าแรกจริงจาก `/yapi2/v1/message/` และ `/yapi2/v1/carousel/` ผ่าน server proxy
- หน้าลงเวลา: กล้องอ่าน QR (เมื่อเบราว์เซอร์รองรับ `BarcodeDetector`), กรอกรหัสเอง, ขอพิกัด GPS และส่งคำขอไป `/yapi2/v1/check`
- ปฏิทิน: แสดงเดือนและขอสถานะจาก `/yapi2/v1/checkstatus`
- คำร้อง: ส่งข้อมูลไป `/yapi2/v1/appealsave` และไฟล์แนบไป `/yapi2/appealupload.php`
- หน้าแผนที่ใช้ OpenStreetMap เมื่อผู้ใช้อนุญาตตำแหน่ง
- QR Generator สำหรับเวรเช้า/บ่าย/ดึก: ถอดรหัสจากภาพแอปเดิมได้เป็น `working1`, `working2`, `working3` ตามลำดับ รายการขออนุญาต 2 ชั่วโมงยังไม่มี payload ที่ยืนยันได้
- หน้าโปรไฟล์แสดง Web Device ID ของเบราว์เซอร์และมีทางลัด QR Generator / GPS Testing; รหัสนี้ไม่ใช่ Android UDID
- บัญชี: ส่งคำขอ `/yapi2/v1/login` และ `/yapi2/v1/register`; token เก็บใน React state เท่านั้น

## ข้อจำกัดที่ต้องยืนยัน

ไม่มีเอกสาร API หรือบัญชีทดสอบ ฟังก์ชันที่ต้องล็อกอินจึงใช้ชื่อฟิลด์ที่อนุมานจาก APK และยังไม่ผ่านการทดสอบกับบัญชีจริง ตัวเว็บจะไม่แสดงผลสำเร็จหาก API ส่ง HTTP error แต่ schema การตอบกลับบางแบบอาจต้องปรับ `app/page.tsx` และตัวกลาง `app/api/ytime/[action]/route.ts` เพิ่มเติม เมื่อได้ตัวอย่าง request/response หรือทดสอบกับบัญชีที่ได้รับอนุญาต

## รันในเครื่อง

```text
npm install
npm run dev
```

ตั้ง `YTIME_API_BASE_URL` ใน environment หากเซิร์ฟเวอร์เปลี่ยน ดู `.env.example`. ห้ามเก็บรหัสผ่านหรือ token ใน source. Site ที่เผยแพร่เป็น private ตามค่าเริ่มต้น.
